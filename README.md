# Cadence Reader

A Windows document reader built around natural, private text-to-speech. All 23 Kokoro English voices run on your CPU, with the original eight available under the Curated voices filter. No API key is required.

## Open the reader

Double-click `Start Cadence.cmd` in this project folder, or `release/win-unpacked/Cadence.exe`. This is a self-contained Windows x64 application folder; keep `Cadence.exe` and the other files in `win-unpacked` together. No Node.js installation is required to run the packaged app. The voice model and voice files are included, so local narration works offline from the first launch. This workspace uses the approved `%USERPROFILE%\CadenceReaderData` folder for the live library, settings and saved export jobs, independently of the application folder.

If there is no packaged build, `Start Cadence.cmd` launches the installed Electron runtime and the existing `dist` build.

## Reading and listening

- Import PDF, DOCX, EPUB, TXT or Markdown files, or paste text into a new document. Drop multiple files anywhere in the app to import them together.
- **Voice → All voices** shows the same 23 English voices available in Kokoro export, including Sky, Kore and Puck. **Curated voices** keeps the original Heart, Bella, Nicole, Sarah, Michael, Fenrir, Emma and George choices. Accent and gender filters search the full catalog. Preview a voice before you listen; all work offline on the CPU reader as well as the GPU exporter.
- Play, pause, skip passages, jump 15 seconds, and adjust playback speed from 0.65× to 1.75× with pitch compensation. Quick start plays the first prepared phrase while upcoming speech generates in the background. Clips share one continuous Web Audio clock.
- Click any word in Reading view or the original PDF to begin at that exact word. The selected suffix is synthesized directly; playback does not estimate a word timestamp. Dragging still selects text. Keyboard activation of a passage starts at its beginning.
- PDF narration skips well-supported repeated running headers, footers and page numbers, including combined title/page-number lines. New imports also check small-font margins farther inside the page. Already-saved PDFs benefit without reimporting or changing their source indices, bookmarks or browsing checkpoints. Repeated decorative font codes attached to a paragraph are excluded from speech while preserving exact body-word offsets. Playback and WAV export use the same exclusions; original PDF pages remain intact.
- Browse freely during narration: scrolling and original PDF page navigation do not change the audio or pull the view back. **Go to audio** returns to the spoken passage or page. **Follow audio** optionally keeps narration in view; scrolling or changing PDF pages turns following off again. Following is off when opening a document.
- **Navigate** opens a document sidebar with page previews, filtering, a browsing highlight and a separate headphones marker for audio position. Reading view preserves original PDF page boundaries, including pages without selectable text. The page jump box and previous/next buttons browse without moving audio. PDFs with embedded page labels show those labels alongside physical PDF page numbers. Switching between Reading view and Document view keeps the browsed location. Existing library PDFs gain embedded labels when opened; reimport is unnecessary.
- **Navigate → Contents** preserves the book's hierarchy: parts, chapters and main topics appear first, with subsections behind expand arrows. Opening material is grouped separately. Expanding a branch never moves the reader or audio. Search keeps matching subsections under their parent; the location breadcrumb and explicit locate button help you return to your current chapter without the sidebar scrolling by itself. Browsing and audio have independent markers. Expanded branches are remembered per document.
- PDF bookmarks provide the preferred structure, including named and bare chapter labels. When bookmarks are absent, the app uses chapter labels and font hierarchy, suppressing repeated running headers and contents-page duplicates. Printed contents entries are used only with verified text or page-label destinations; uncertain documents retain page navigation. Reading-view jumps target the heading paragraph when matched, and Original PDF jumps honor the bookmark's position within the page. Multiple headings on one page remain separate. **Pages** is always available, with groups of 40 previews and search across the whole document. Existing saved books rebuild their index on opening without reimport; the refresh button rebuilds it again on demand. This runs locally, with no AI service or document upload.
- **Menu** at the top left opens the library toolbar as a temporary drawer over the reader. It starts closed on every launch. Choose an action, press Escape, click outside, or use Close menu to dismiss it without resizing the document. **Navigate** and the contents panel's close button independently hide or restore document navigation; that choice is remembered.
- Word heading styles and Markdown heading levels retain their hierarchy in Contents. TXT and pasted documents use detected chapter labels or headings. Section navigation remains available, falling back to groups of passages. These formats can reflow and their extracted text does not retain reliable original page boundaries, so the reader does not assign original page numbers to them.
- **Document view** is available for PDF, EPUB, DOCX, TXT, Markdown and pasted notes. PDFs retain their original pages; other formats use a clean book layout with the imported headings, chapters and paragraphs. Reflowable documents use sections rather than invented original page numbers. This does not recreate publisher styling or original Word pagination from the extracted text.
- PDF Document view scrolls continuously through original pages, including blank pages and mixed page sizes. Scrolling updates the browsing page and Contents marker while narration keeps its own position. **Go to audio** reveals the current spoken sentence or phrase once; **Follow audio** scrolls with narration within and across pages when enabled. Manual scrolling or page navigation turns following off. The page arrows/jump box, exact-word clicks, zoom, search and exclusive speech cues remain available. Full screen includes a Follow audio toggle too. Other formats retain continuous sections with the same browsing/audio controls.
- Original PDF pages have **PDF zoom** with Fit width and 50–200% of the fitted width. Search jumps to and highlights matching text on its original page; previous/next match buttons cycle through up to 2,000 matches. Zoom and search preserve the audio position and exact-word playback. Typeface/text-size controls apply to reflowed text, and those preferences persist across launches.
- **Bookmark viewed passage** saves the text you are browsing. The separate headphones action bookmarks the audio position. Opening a bookmark reveals its saved passage without starting narration or moving same-book audio. The Bookmarks screen always has **Back to reading** or **Back to library**, returning to where you entered it; Reading view restores the paragraph and original PDF Document view restores the page. Library-title search and document search keep separate state.
- Choose **Speech cue → Highlight** or **Underline** to follow the spoken sentence or phrase in either view. Only the selected cue is shown; pausing holds it and neither choice turns on automatic scrolling. The choice is remembered across launches. In full screen, the highlighter/underline button switches between the two. Search the text, change the typeface or text size, and bookmark passages.
- Your library, original PDF, bookmarks and passage position are saved locally in IndexedDB. File imports are limited to 50 MB each.
- Restarting Cadence reopens the last successfully opened book at its browsed PDF page or text paragraph, including Reading view / Document view mode for all supported formats. Browsing and audio checkpoints remain separate; narration does not start automatically. Each book keeps a compact location, with at most 64 recent checkpoints in one small local-storage record. No document text, PDF bytes, page images or audio are copied into that record. Document view for PDFs resumes at the top of the saved page; reflowable documents and Reading view restore their paragraph. Closing a document or visiting the library keeps the last-book choice for the next launch. Removing a book removes its checkpoint too. Books without a saved browsing checkpoint initially open near their existing audio position.
- **Close document** (× beside the title) stops audio and releases the open reader while keeping the book on your shelf. Removing a book offers **Undo** for ten seconds, preserving its text, original PDF and bookmarks during that window. Dismissing the removal message, removing another book or closing Cadence finalizes the pending removal. External original files are unchanged. **Cancel import** stops the current import and remaining queued files; documents already added stay on the shelf.
- **Export audio** defaults to one chaptered M4B for the entire document or the remaining passages. GPU and CPU Kokoro use the supplied fp32 model. Compare the same passage before choosing: samples remain paused until you press Play. Creating an M4B opens the manager; **Back to reading** returns to your document while conversion continues independently. The existing mono 24kHz/16-bit WAV tool remains available for shorter exports, with its two-hour limit; M4B has no two-hour limit.
- **Menu → Audio exports** is a dedicated manager for ongoing, paused, failed and completed M4B conversions. Search by title or voice, filter All / Unfinished / Completed, inspect progress, saved audio duration, chapters, model, creation date and destination, or reveal a completed audiobook in its folder. Pause/resume and retry preserve completed speech; jobs can resume without their document open. Closing Cadence pauses active conversion; reopening never resumes it or starts narration automatically. Each completed phrase is saved durably, and completed history remains after temporary audio is cleaned up. Short-lived Windows file locks are retried without deleting the previous checkpoint. The older short-WAV tool and WAV files created before this manager are not resumable jobs or retroactively indexed history.
- A sleep timer stops narration after 5, 15, 30 or 60 minutes. Space plays/pauses; arrow keys skip 15 seconds when a form control is not focused.

Reading times, progress and seeking are estimated from the text. The highlight follows scheduled speech phrases, usually complete sentences; short headings or very short sentences can share a phrase. It does not estimate individual word timestamps. PDF narration follows extracted text order, which can differ from visual order in complex multi-column layouts. Scanned PDFs need OCR first. Legacy `.doc` and encrypted PDFs requiring a password are not supported. DRM-free EPUB 2/3 books import as text with chapter/section navigation; fixed-layout presentation and encrypted book text are not supported.

## Reading space and full screen

While reading, the title and document details share a compact top bar. The separate title banner and decorative caption are removed. Long titles stay on one line with the full title available on hover. Reading tools occupy a short row; page navigation and audio-follow controls share another row that wraps on narrow windows. Library and bookmark views retain their own headings. `node scripts/header-qa.mjs` checks long titles, control access, compact-window layout and full-screen behavior; `--baseline` records the current installed build for comparison.

The Voice button in the top bar shows or hides the narrator panel; the panel also has its own close button. Its visibility is remembered. The bottom player uses its original full-size layout, including the waveform, playback controls, progress, sleep timer and export.

The interface uses neutral slate surfaces, blue accents and darker labels. Voice choices and the optional blend form scroll together in short windows while the panel's close button stays reachable. Restored text and chapter/bookmark targets leave room for sticky page labels. Clicking a word with the mouse leaves Space available to pause/resume; intentionally focusing a passage with the keyboard retains normal button activation.

Choose Full screen in the top bar, or press F11 while reading. The desktop window fills the screen, the document uses the available space, and a small side strip provides playback, 15-second skips, current page/section and stepping, navigation, voice selection, speed, Document/Reading view switching, search, original PDF zoom, speech cue selection, bookmarks and a return-to-audio button. Voice and navigation panels open as temporary drawers. Esc, F11 or the side-strip exit button restores the normal layout and panel preferences.

In both normal and full-screen reading, **Hide player** manually collapses the player. Mouse movement and scrolling leave it hidden; click the small **Playback** handle, click another control or press a deliberate keyboard key to bring it back. The automatic 10-second idle collapse also remains; ordinary mouse movement reveals an automatically collapsed player. Collapse frees reading space in the normal view; in full screen the player overlays the document without moving it. Keyboard users can Tab to the Playback handle and use Enter or Space. Narration and its prepared audio queue continue through layout changes. Original page numbers remain visible in Reading view.

`node scripts/reading-space-qa.mjs` checks panel preferences, both reading views, reading position, uninterrupted playback, hover and keyboard access, full-screen shortcuts, restoration and compact-window layout. `node scripts/chrome-ui-qa.mjs` checks manual player hiding, the Menu drawer, Bookmarks return and paused restart using an isolated library. Pass `--staged` to check the prepared desktop release.

`node scripts/structure-navigation-qa.mjs --staged` checks hierarchical bookmarks, exact same-page heading jumps in both views, novel chapters without bookmarks, Markdown/Word heading levels, page groups, old-index migration, independent audio/browsing, saved expansion, and compact layouts. It also checks the source Poor Charlie book when present in Downloads. `book-topic-check.mjs` accepts PDF paths for a structure-only check, with regression assertions for the Munger and Varian books.

`node scripts/resume-qa.mjs --staged` closes and relaunches the actual desktop process against one isolated test library. It checks book/page/paragraph restoration, immediate close after a jump, original-PDF mode, separate audio and browsing positions, pending bookmark writes, multiple books, Close document, the library view, blank pages, deletion and small checkpoint storage. On normal exit the desktop waits for pending summary saves and flushes browser storage, with a timeout for an unresponsive renderer. A second launch focuses the existing instance instead of opening competing library writers.

## Memory and document lifetime

The shelf stores compact summaries, with text and original PDF files in separate IndexedDB records. Only the selected document's text is loaded; original PDF bytes are read only for original-page viewing or a one-time navigation metadata upgrade. Position and bookmark saves update summaries without cloning any book contents. Existing libraries migrate in one atomic transaction. An empty library remains empty after restart.

Reading view keeps page landmarks and native paragraph text near the viewport, plus explicit navigation and audio targets. Speech, search and hover use native text ranges instead of individual word boxes. Measured placeholders preserve scroll positions. Continuous original PDF view reuses one PDF.js document/worker and renders at most eight nearby pages. Lightweight placeholders and numeric page aspect ratios preserve the scroll layout; distant canvases, text layers and highlight ranges are released. Closing the viewer destroys its worker and remaining canvases. Completed speech clips have a 24 MB / 48-entry LRU ceiling, independent of the rolling playback queue; changing or closing documents drops the previous document's cache. Voice previews release object URLs when stopped.

The full-precision voice model stays loaded to keep playback responsive. ONNX memory-pattern caching is disabled for varying phrase shapes; the CPU memory arena, thread pool, voice quality, and playback lookahead remain enabled. The engine still has a substantial baseline memory cost, and import/rendering can briefly increase memory before runtime garbage collection releases temporary allocations.

`node scripts/memory-qa.mjs` checks migration, bounded page rendering, navigation/playback, metadata-only saving, document switching/removal, import cancellation and PDF worker lifetime. `node scripts/memory-profile.mjs "path-to-book.pdf"` measures process working sets through import, playback, repeated imports and close; pass `--staged` for a staged release. `model-memory-benchmark.mjs` compares ONNX allocation settings against the same phrases.

`node scripts/continuous-pdf-qa.mjs` checks vertical PDF scrolling, independent browsing, sentence following across pages, paused Go to audio, exact-word/Space playback, search/zoom, full-screen following, a 200-page rendering bound, mixed sizes/blank pages, idle-player jump priority, complete-process restarts, cleanup and non-PDF Document view following. Pass `--staged` for the prepared desktop build. Its synthetic books and profile are isolated under `test-results/continuous-pdf/`.

`node scripts/scroll-performance-qa.mjs --smooth-only --assert` verifies that loading pages does not interrupt native scrolling. The default run measures forward, reverse and playing wheel input; `--fixture "path-to-book.pdf"` uses an original book in a separate test library. Add `--staged` for the prepared build or `--baseline` to profile the installed copy. Reports are under `test-results/scroll-performance/`. Unchanged page measurements and no-change layout anchors avoid resetting Chromium's scrolling animation.

`node scripts/playback-performance-qa.mjs --visible --assert` measures idle, real offline narration and paused scrolling in an isolated library, recording UI commits, frame intervals, event-loop delay, renderer work, CPU profiles and audio scheduling. An optional `--fixture "path-to-book.pdf"` uses a real book; otherwise it generates synthetic pages. Add `--reading` for Reading view, `--speed 1.5` for another narration speed, `--baseline` for the installed app or `--staged` for the prepared build. Reports are under `test-results/playback-performance/`. Estimated timeline updates are limited to five per second, while sentence cues and audio scheduling retain their original audio-clock timing; unchanged reading sections and navigation reuse their existing render.

## Smooth playback

Settings → Smooth playback defaults to **Quick start**, which schedules the first phrase immediately when ready. Optional 3- or 8-second audio reserves remain available for slower computers. The previous 12–60-second startup setting is migrated to Quick start. A rolling queue prepares about 20 seconds ahead, with at most 12 phrases in memory.

The local engine loads in parallel with the app window. Opening a document prepares its first three speech units for the selected local voice, without playing them. Narration now uses complete sentences instead of fixed 110/180-character fragments. Shared in-flight requests, raw PCM playback, and cancellation of obsolete queued work reduce startup and word-jump delays. Natural punctuation and short headings are preserved. The full-precision Kokoro model uses a bounded CPU thread pool; on the development computer it outperformed the smaller dynamically quantized model, without changing voices. The bundled model is about 326 MB.

Playback plans text incrementally as the rolling queue needs it, preserving the same sentences and source-word offsets without building the remaining book's entire plan on every start. A clicked passage begins synthesis alongside output setup. The reader keeps one active audio context and one silent prepared context; each retired session closes its context so old SoundTouch processors cannot accumulate. Pausing retains the current clock, and reader close releases both contexts. This prepares output without starting narration or increasing the speech reserve.

Within mounted reading sections, paragraphs retain their original visible, accessible text and natural height. Native speech/search ranges are limited to nearby paragraphs, explicit targets, spoken passages and retained selections. Hover resolves one word at the actual pointer and waits for scrolling to settle; word clicks use real glyph coordinates and exact source offsets. A token fallback remains for environments without CSS Highlight support. `scripts/reflow-performance-qa.mjs` checks long chapters, selection and Go to audio during a smooth scroll; `scripts/output-lifetime-qa.mjs` checks repeated starts and native audio-context limits. Both accept `--staged`. `scripts/startup-performance-qa.mjs` measures process-cold scrolling and real narration with synthetic text by default or a large synthetic PDF with `--pdf`; `--smooth` measures actual animated scroll movement, `--jumps` checks new/cached starts, `--accessibility` enables the test process's accessibility tree, and `--baseline`/`--staged` select desktop artifacts. Use distinct `--tag` values and `--seconds 245` for long comparisons. CPU/timeline sampling is optional and should be reported separately from unprofiled timings.

Reading-view paragraphs have no speech-length cap. PDF extraction uses measured line spacing with a rounding tolerance, plus paragraph gaps, short completed lines, indentation and font changes. Opening an older book conservatively joins unfinished blocks on the same page and atomically remaps saved passage positions and bookmarks; it does not need to load the original PDF. Complete sentences from older imports remain separate display blocks when their original paragraph layout is unknown. Narration can join an unfinished sentence across a page boundary while retaining exact word-click mappings.

The worker checks actual phoneme tokens before inference, disabling Kokoro's silent truncation at its 512-token context limit. Exceptionally long sentences are subdivided at clauses when possible, or at words when there is no suitable clause, and joined with conservative padding trimming. An unusually long first sentence can take longer to synthesize; the reader does not wait for an entire paragraph or book. WAV export uses the same sentence plan without the old extra 180ms silence per display block. `paragraph-qa.mjs` checks old-book repair, marker preservation, exact-word playback and long-paragraph export; `paragraph-voice-check.mjs` checks the captured source-page fixture and actual local speech.

Audio is decoded before it is needed. Each clip is scheduled at the preceding clip's exact end time, and passage highlighting follows the audio clock. Pausing freezes that clock; changing speed reschedules ready clips and uses SoundTouch pitch compensation. Long, near-silent padding at clip edges is trimmed conservatively, retaining breathing room and pauses within sentences.

If sustained generation is slower than the listening speed, buffering can still occur. First launch, an uncached word jump, and heavy CPU load can take longer. Native inference already in progress cannot be interrupted; its result is discarded after cancellation and the latest interactive request runs before queued background work. For a full pre-render, use Export audio.

This is phrase-level pipelining: Kokoro returns each phrase after inference completes. It is not a token-streaming speech model and does not reproduce ChatGPT Voice's private infrastructure. OpenAI's public [speech API](https://developers.openai.com/api/docs/guides/text-to-speech) streams audio before a full file is generated, while its [Realtime API](https://developers.openai.com/api/docs/guides/realtime-conversations) supports native speech-to-speech. Those hosted systems and this offline CPU model have different latency limits.

## Local voice choices and EPUB books

The Voice panel starts with the same eight curated voices. Choose **Extended voices** in its filter to show all 23 English voices. **Blend voices · experimental** lets you choose two voices and their ratio, then select **Use blend**. Preview, playback, export and restart use that selection. Pronunciation follows the first voice, except a 0% blend uses only the second voice. All voice files are already bundled; blending does not require another model or a download.

EPUB import reads DRM-free EPUB 2/3 chapters in spine order and preserves nested EPUB navigation/NCX contents and heading levels. It extracts text without running book scripts or loading remote resources. The reader uses sections rather than physical PDF page numbers. ZIP entries are checked for integrity, paths and bounded expansion (20 MB per entry, 128 MB total). Font-only obfuscation can be ignored because fonts are not imported; encrypted text is rejected.

PDF import removes confirmed repeated margin text and page numbers. Existing books keep their saved text indices, positions and bookmarks; narration conservatively skips repeated edge passages without rewriting their text. Original PDF word clicks continue to map to the retained body text. Export stores 16-bit PCM chunks and uses the same sentence/paragraph/heading pause bounds as playback. Heading breaks are paced at their known source boundary instead of guessing which internal pause belongs to a heading.

## Development

The approved optional audiobook runtime is local to `.cache/audiobook`: portable CPython/CUDA and FFmpeg. Prepare it with `powershell -ExecutionPolicy Bypass -File scripts/setup-audiobook.ps1`; no global Python/driver installation is needed. Keep this cache with the workspace when using the unpacked app. Generation is offline. Setup pins package versions and verifies tool checksums. A changed upstream FFmpeg download fails its checksum rather than silently installing a different build. Qwen was removed at the user's request; shared Kokoro/CUDA files remain.

For this workspace, the approved stable library and saved-export location is `%USERPROFILE%\CadenceReaderData`. Windows can redirect AppData for apps started by a packaged host such as Codex; this explicit local path makes desktop and Codex launches use the same data. Original AppData profiles and the recovery snapshot are retained. Tests must always use isolated `CADENCE_DATA_DIR` folders under `test-results`; QA refuses to start without an explicit folder. The migration ZIP remains a snapshot; OneDrive does not synchronize this live database.

Chatterbox is a separate, approved offline trial, not a Cadence export option. `scripts/setup-chatterbox-trial.ps1` prepares its isolated environment and verified, pinned full-precision Turbo ONNX model in `.cache/chatterbox-trial`. Run its environment's Python with `scripts/chatterbox-trial.py .cache/chatterbox-trial <mono-24kHz-synthetic-reference.wav>`. The trial uses a synthetic Kokoro reference, leaves Kokoro unchanged, and disables automatic CPU retry so a GPU failure cannot silently become a CPU benchmark. See `docs/RECOVERY_AND_CHATTERBOX_2026-11-06.md` for results and limitations.

M4B uses AAC at 96kbps (about 43MB per audio hour) with flat chapter markers; nested titles retain their hierarchy as breadcrumbs. Temporary PCM requires about 173MB per audio hour on the profile's drive, plus space for the final output, and is removed after successful output validation. Saved jobs retain their source/settings until completion; deleting their private job folders prevents resuming. Existing output files are protected. M4B exports can stop their isolated helper immediately and regenerate only the unfinished phrase when resumed. The older WAV path finishes its current native phrase before stopping. Everyday narration keeps its existing CPU backend. See `docs/AUDIOBOOK_EXPORT_PLAN_2026-11-06.md` and `docs/AUDIOBOOK_EXPORT_CHANGES_2026-11-06.md` for historical measurements and limits; Qwen references there describe the superseded build.

Requires Node.js 22 or newer, npm, and Windows x64 for the desktop build.

```powershell
npm ci
npm run desktop
```

`npm run dev` serves a browser preview of the interface. Neural speech requires the desktop app.

```powershell
npm test
npm run build
npm run test:integration
node scripts/voice-check.mjs
npm run package
```

`voice-check.mjs` downloads the roughly 326 MB full-precision Kokoro model to `.cache/models`, generates eight real voice samples and checks their WAV headers. Run it before packaging; `electron-builder` bundles that model directory along with the application, excluding the old quantized model. The model and runtime use native CPU inference inside a worker thread, keeping the interface responsive.

`npm run package` creates the self-contained application folder. An optional `npm run package:portable` command creates a single-file portable wrapper; the initial wrapper build stalled after compression, so the delivered, verified build is the application folder.

The integration suite launches an isolated, hidden Electron instance with a fresh library. It tests voice selection, real neural playback, WAV generation and saving, PDF rendering, DOCX/TXT imports, bookmarks, search and persistence. Test fixtures, screenshots, voice samples and reports are written to `test-results/`. To run against the unpacked release, set `CADENCE_QA_EXECUTABLE` to the absolute path of `release/win-unpacked/Cadence.exe`.
