## Architecture

- `speechPlan.ts` now has one canonical incremental iterator. Playback pulls complete immutable speech units as needed; the array API used by export and existing callers collects that same iterator. It preserves tiny-heading merges, abbreviations, continuation across PDF pages, omitted margins, transport bounds and exact original character ranges. Shared `Intl.Segmenter` instances avoid repeated construction.
- `segmentSource.ts` supplies the narrator with a rolling metadata queue. The existing 12-phrase/time audio reserve remains unchanged. One metadata lookahead provides the next boundary for pacing and detects EOF, including a long last clip. Consumed metadata is released alongside audio (two previous units retained). A new clicked source word creates a new iterator rather than scanning/retaining the remaining book. A 50,000-passage unit case reads fewer than 20 text properties to obtain its first speech unit; a 10,000-unit advancing queue retains at most 15 metadata items in its tested access pattern.
- `PlaybackContext` keeps at most one active context and one suspended prepared context. Silent device/worklet preparation runs alongside the existing opening preparation and replenishes the standby after playback begins, without generating additional speech. Each new start consumes the prepared context; retiring a session closes its context and SoundTouch processor completely. Reader close/unmount closes both; a document switch stops the active session while the generic silent standby can be reused. Explicit playback starts synthesis in parallel with output setup, so an uncached click does not wait for device/worklet setup. Failed or superseded starts still abort their requests and discard stale audio.
- `ReadingPassage` keeps the natural text/button layout with visible native paragraph text. Speech, search and hover use CSS Highlight ranges instead of thousands of inline word boxes. One shared viewport observer bounds decorated text runs; distant paragraphs keep their original text and height, and selected nodes stay pinned until selection clears. Pointer hover resolves just one actual word and waits for scrolling to settle. Exact clicks use the caret and real glyph rectangles, including final-glyph edges and RTL words. A token-span fallback remains for environments without native highlight support. Text is not hidden from accessibility. Section landmarks, source offsets, keyboard controls and independent browsing/audio remain intact.
- `speechBuffer` copies PCM directly into the AudioBuffer, avoiding an unnecessary temporary Float32 clone. Samples and precision are unchanged.
- Go to audio now uses the existing bounded explicit-navigation reanchor for reflowable text too. It interrupts an ongoing smooth browse reliably; manual input cancels that one-shot positioning and following stays opt-in.
- Worker model notifications check that the window and its web contents still exist. On application close, queued work is cancelled and the worker finishes its current native call, disposes model sessions and closes naturally before the main process quits. This addresses the user's screenshot (`Object has been destroyed`) and a separate native termination race reproduced with the installed baseline; it does not alter normal synthesis scheduling.

No model, inference thread/priority policy, startup reserve, sentence size, permanent audio cache bound, dependency, lockfile, storage schema, migration or visual theme change is included. No test uses the live `%APPDATA%\Cadence` library.

## Tradeoffs and limits

- Silent device/worklet preparation moves a short initialization cost into opening/preparation. There is no extra speech reserve or new model work. The standby uses an additional suspended native context while a session is active; the measured resource cap is two contexts, both closed when the reader closes.
- Native text ranges replace per-word elements in bundled Chromium. Visible text, selection and source offsets remain intact. This adds range/hover lifecycle code; hover is withheld during scrolling and returns after about 160ms of settling. A token renderer remains for older browser environments. Long-chapter, Unicode, RTL, final-glyph, selection and cleanup checks cover the new path.
- Closing while native model loading or generation is active can leave a background cleanup interval after the window disappears. Focused source cases took about 4.0–5.7s and observed both worker and app exit codes of zero; ordinary reading/start/jump latency is unaffected by this exit-only path. A particularly long or hung native call can take longer. The updater preserves the existing build if its process is still busy. Forced native termination is not used as a successful-close substitute.
- New speech still needs full-precision inference, and an already-running native call cannot be interrupted immediately. Early interactive dispatch overlaps output setup; it does not make every new word cached or promise instant uncached speech. First Play timing also depends on how much speculative preparation has finished. Reports record both click-to-scheduling and launch-to-scheduling to avoid mistaking an earlier visible reader for slower total readiness.
- The user's full 2–3-minute severe-lag duration was not reproduced in the original diagnostic. Final four-minute comparisons cover the relevant window in isolated profiles, rather than certifying every live-profile/OS/audio-driver condition. No GPU, driver or inference-thread change is included.
