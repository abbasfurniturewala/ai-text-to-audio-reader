## Implementation

- `desktop/audiobook-encoding.mjs` owns one bounded background AAC process at a time. Windows priority is Below Normal (native tests read back priority10); inference remains in the existing separate helper. Compression starts once about two audio minutes plus context are durable. Selecting quiet frame boundaries within ten seconds before the target reduces boundary sensitivity. No model chunk size or narration pause changes.
- Each section is frame-aligned AAC-LC with six frames of real PCM context before/after where available. Internal encoder priming and trailing padding are removed. The assembled stream retains exactly one global1024-sample priming frame; FFmpeg packet timestamps/last duration and an explicit MP4 edit list represent the exact original sample count. There is no naive concatenation of independent M4A files and no AAC→AAC transcode during assembly.
- Temporary sections and descriptors are synced before atomic commitment. Descriptors bind source hash, model identity, encoder binary hash, encoding format, sample interval, frame count, bytes and SHA256s for both PCM and AAC. Restore validates the prefix. Corrupt/incomplete compressed sections rebuild only the suffix. Changed raw narration halts with the good compressed sections retained, rather than overwriting them from unexpected PCM. Interrupted private files are never exposed as completed audiobooks.
- `desktop/audiobook-jobs.mjs` queues only committed PCM after the existing per-phrase checkpoint; no audio is held in a growing memory queue. It retains PCM until successful validated publication. Pause cancels synthesis and the current encoder, retaining completed sections. At most the interrupted section (about two audio minutes, normally seconds of encoding time) is repeated. Assembly can be retried from cached AAC; already-valid completed private M4Bs still use the previous completed-file reuse path.
- Existing version1 jobs, source fingerprints and narration model identities remain valid. An optional `encodedSamples` summary/checkpoint field reports durable compression; section descriptors remain authoritative after restart. Active refresh uses the verified in-memory count. No reader-library schema/version/migration changes. Legacy PCM-only jobs build compressed sections once, then benefit from reuse; they do not acquire already-completed compression for free.
- Export manager shows compressed-and-saved duration and separates remaining compression, assembly, indexing, checking and saving. ETA for resumed compression measures only newly processed work. No automatic narration/conversion resume. UI and backend temporary-space estimates use the same updated allowance.

## Tradeoffs and limits

One CPU encoder now works during synthesis; Below Normal priority and bounded buffers protect interactive work, but zero contention on every machine cannot be promised. Temporary AAC sections add about43MB per audio hour, in addition to about173MB/hour PCM and assembled output. Resume verifies saved files, adding a disk-check delay (6s in this warm-cache15-hour test). Cache interruption loses at most the current section's compression; it does not restore a native encoder's internal state mid-frame. Initial legacy-job compression remains necessary. Slower storage, CPU contention or unusually fast synthesis can leave a larger final backlog. External Apple/Android audiobook-player testing and subjective listening remain outside the Windows checks.

Suggested commit: `perf: overlap audiobook compression and retain encoded checkpoints`.
